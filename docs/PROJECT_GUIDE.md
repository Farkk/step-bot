## Текущее состояние

| Область | Реализовано | Следующий рубеж |
| --- | --- | --- |
| Go-приложение | HTTP-сервер, проверки здоровья, API профиля и полный цикл заявки; динамические поля, вложения, события, оценка, репутация, аналитика и роли | Редактирование опубликованной заявки и восстановление пароля |
| Бот Max | Webhook с проверкой секрета и идемпотентной записью JSON; обработка callback «Откликнуться», карточка новой заявки с кнопкой и push из очереди | Проверка доставки и callback в реальном Max |
| Mini App | Регистрация профиля, лента и детали заявки с полями/вложениями, отклик, активные и архивные заказы, смена статуса, реальная репутация | Проверка UX в реальном Max |
| Кабинет заказчика | Вход, создание заявки с динамическими полями/координатами/файлами, отклики с рейтингом и статистикой, журнал, оценка, аналитика/CSV, управление ролями | Редактирование заявки и восстановление пароля |
| PostgreSQL | Миграции `001`–`005`: профили, компании, сотрудники, заявки, события, шаблоны полей, оценки, метаданные вложений, inbox и outbox | Политика хранения персональных данных |
| S3/MinIO | Автоматическое создание bucket, загрузка и скачивание вложений через подписанные сервером запросы | Политика хранения и очистка неиспользуемых объектов |
| Docker | Один образ приложения с Go и React; Compose поднимает `app`, `postgres`, `minio`; на VPS используется общий Traefik с HTTPS | Резервное копирование и проверка восстановления данных |

`GET` и `PUT /api/v1/me/profile`, а также маршруты `/api/v1/worker/*` проверяют данные запуска Max из `X-Max-Init-Data`; рабочие маршруты требуют сохранённого профиля. В локальном режиме `local-preview` разрешён только с loopback. Админские маршруты используют `HttpOnly` cookie и CSRF-токен. Webhook фиксирует событие до ответа, отдельный worker обрабатывает callback идемпотентно. Исходящие Push-сообщения отправляет фоновая очередь при наличии токена бота.

## Карта кода

- `cmd/server` — запуск, команда миграций, остановка по сигналу.
- `internal/config` — чтение окружения.
- `internal/httpserver` — маршрутизация, health checks, статические файлы.
- `internal/max` — входной webhook, исходящий клиент Bot API и фоновая доставка из `notification_outbox`.
- `internal/storage`, `migrations` — PostgreSQL, миграции и S3 SigV4 для вложений.
- `internal/admin` — вход, сессии, роли и разовое создание владельца; `internal/tasks` — заявки, отклики и переходы статусов.
- `internal/profile` — чтение и сохранение профиля по подтверждённому Max ID; `internal/max/launch.go` — проверка подписи и срока данных запуска/телефона.
- `web/miniapp/src/app` — экран первого запуска и рабочие экраны исполнителя (`Dashboard.tsx`); `src/features/profile` — клиент API и правила формы. Функции Mini App добавлять в `src/features/<сценарий>` с отделением API, состояния и UI по необходимости.
- `web/admin/src` — экран входа и кабинет с заявками, событиями, оценками, аналитикой и командой. `RealAdmin.tsx` вырос; следующий рефакторинг — разделить по `features`.
- `infra/minio` — образ MinIO из официального бинарного релиза; `compose.yaml` — три сервиса и тома; `compose.vps.yaml` — сеть общего Traefik и HTTPS-маршруты.

Бизнес-правила размещать в серверных модулях, не в webhook-обработчике и не в React. При появлении второго React-приложения общие токены и компоненты вынести в пакет `web/packages`, не дублируя их по приложениям.

## Применение дизайн-системы

Форма первого запуска Mini App оформлена в тёмной теме. При развитии следующих экранов:

1. Выбери нужный сценарий из раздела 6 `DESIGN_SYSTEM.md` и сверь его с функциональным контуром `TECH_SPEC.md`.
2. Заведи в коде базовые, семантические и компонентные токены по разделам 3 и 9 дизайн-системы. Компоненты должны использовать семантические роли; конкретные hex-значения остаются в токенах.
3. Для Mini App используй тёмную тему и мобильную одноколоночную компоновку; для будущего кабинета — светлую тему. Сохраняй единые названия статусов и действий в UI и сообщениях бота.
4. Проверяй текстовые статусы вместе с цветом, контраст, зону нажатия, фокус, длинные русские строки, загрузку, пустое состояние и ошибку.
5. Запиши новые экраны, компоненты и отклонения от дизайн-системы в этом документе. Если отклонение становится новым правилом, обнови `DESIGN_SYSTEM.md`.

## Рабочий срез заявок · 25 сентября 2026

- Первый владелец создаётся командой `create-owner` с параметрами компании, email и имени; пароль передаётся через `ADMIN_INITIAL_PASSWORD` (минимум 12 символов). Публичной регистрации сотрудников нет. Пароль хранится как bcrypt-хеш. Вход ограничен десятью неудачными попытками с одного IP за 10 минут и выдаёт семидневную сессию; cookie `Secure` вне `APP_ENV=local`, `HttpOnly`, `SameSite=Strict`. Изменяющие запросы требуют CSRF-токен.
- `POST /api/v1/auth/login`, `GET /api/v1/auth/session`, `POST /api/v1/auth/logout` управляют сессией. `GET/POST /api/v1/admin/tasks` ограничены компанией; создание доступно владельцу и менеджеру. `GET /api/v1/admin/tasks/{id}/applications` показывает отклики; `POST .../{application}/decision` принимает или отклоняет. Принятие выполняется в транзакции с блокировкой заявки: один исполнитель назначается, остальные ожидающие отклики отклоняются.
- `GET /api/v1/worker/tasks` показывает все открытые заявки зарегистрированным исполнителям (согласованное правило). `POST /api/v1/worker/tasks/{id}/applications` создаёт один отклик на пару исполнитель/заявка. `GET /api/v1/worker/orders` показывает назначенные и завершённые заказы; `POST /api/v1/worker/orders/{id}/status` разрешает назначенному исполнителю последовательно начать и завершить работу. Действия фиксируются в `task_events`.
- Реальная лента и профиль Mini App обновляются при возвращении в приложение. Репутация рассчитывается сервером. Кабинет показывает реальные данные заявок, откликов, журнала, оценки и аналитики. Восстановление пароля и редактирование опубликованной заявки ещё не реализованы.
- `go test ./...`, `npm test` и сборки обоих клиентов проходят. Контейнер пересобран, `/health/ready`, `/app/`, `/admin/` отвечают `200`, закрытый `/api/v1/admin/tasks` — `401`. Сквозная проверка через HTTP прошла: временный владелец вошёл, создал заявку, исполнитель откликнулся, заказчик принял отклик, исполнитель начал и завершил заказ; тестовые данные удалены.
